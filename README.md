# sltranslator.com

Next.js 15 (App Router) + React 19 + TypeScript.

```bash
npm run dev        # http://localhost:3000
npm run build      # production build
npm start          # serve the build
npm run lint
npm run typecheck
```

## `_archive/`

Holds one file: `legacy-sources.tar.gz` (281K) — the original 18 HTML pages,
their stylesheets and scripts, plus the old `.htaccess`, `robots.txt` and
`sitemap.xml`. Extract with:

```bash
tar xzf _archive/legacy-sources.tar.gz
```

The legacy *images* are not in it: all 429 of them were verified byte-identical
to the copies now under `public/`, so keeping a second set would be dead weight.
The abandoned Next.js scaffold that used to sit here (89M, mostly a stale
`.next` build) has been deleted outright.

## Root-level files like `ads.txt`

`ads.txt`, `llms.txt` and `sw.js` live in `public/` and are served from the site
root (`/ads.txt`, …) — that is how Next.js serves static files. `robots.txt` and
`sitemap.xml` are no longer files at all; they are generated by
`src/app/robots.ts` and `src/app/sitemap.ts`.

## How a page is put together

Each `page.tsx` exports `metadata` built by `buildMetadata()` from
[`src/lib/seo.ts`](src/lib/seo.ts), imports its own stylesheet, and renders its
content. The header and footer come from the root layout, so pages contain only
their own content.

```tsx
export const metadata: Metadata = buildMetadata({ title: "…", path: "/…" });

export default function Page() {
  return (
    <>
      <JsonLd data={structuredData} />
      <main>…</main>
    </>
  );
}
```

### Styling

Every route imports one stylesheet from `src/styles/`. There is deliberately no
large site-wide stylesheet: the original pages shared no common leading rules,
so hoisting them into one global sheet would change which rules win. The six
alphabet-language pages additionally share `alphabet-page.css`, which **must**
be imported before the per-language file — concatenating the two reproduces the
original stylesheet in its original order, and that ordering is what keeps the
cascade correct.

`<img>` is used rather than `next/image` on purpose: the stylesheets size images
through class selectors (`.alphabet-card img`, `.sign-image img`), and
`next/image` renders its own wrapper with explicit dimensions, which would break
those rules.

### Adding a sign language

1. Drop the letter images in `public/<name>-sign-language/`.
2. Add the letter → image map to [`src/data/alphabets.ts`](src/data/alphabets.ts).
3. Create `src/app/<name>-sign-language/page.tsx` rendering
   `<Translator alphabet="…" heading="…" convertLabel="…" />`.
4. Add the route to [`src/data/routes.ts`](src/data/routes.ts) so it reaches the sitemap.

## The blog is still WordPress

`blogs/` is a WordPress install and was **not** migrated. Its posts live in the
MySQL database `u837046115_sltranslator` on the production host — there is no
SQL dump in the repo, no local MySQL, and the live domain is not reachable from
this machine, so the content could not be read, let alone converted.

To finish that migration, provide any one of:

- a `mysqldump` of the WordPress database, or
- a WordPress WXR export (Tools → Export → All content), or
- network access to `https://sltranslator.com/blogs/wp-json/wp/v2/posts`.

With the content in hand the remaining work is a `/blog` route group, a post
renderer, and redirects from the old `/blogs/...` permalinks. Until then the
WordPress install keeps serving `/blogs` and nothing in this app shadows it.

## What changed in behaviour

These were bugs in the old pages, fixed as part of the conversion:

- `hre="…"` instead of `href="…"` — 15 dead links across 9 pages.
- Four pages used Font Awesome icon classes without loading the font, so those
  icons never rendered. Fonts are now loaded once in the layout.
- The baby-sign page shipped modal CSS but never rendered the modal markup, so
  clicking a sign card threw a `TypeError`. The modal now works.
- Analytics and AdSense ran on the home page only; they are now site-wide.
- `og:image` / `twitter:image` on the home page pointed at a pre-reorganisation
  path that only resolved through an `.htaccess` rewrite.
- The footer had seven different link sets; all pages now use the one that 16 of
  the 18 pages already had.

Deliberately left alone:

- The nav's current-page highlight. The old markup used a valueless `active`
  attribute while the stylesheet targets the `.active` class, so it never
  rendered. Pass `highlightActive` to `SiteHeader` to switch it on.
- `public/sw.js` is a third-party push-notification worker that loads code from
  `5gvci.com`. No page registers it, so it is inert — but it is worth deciding
  whether it should be there at all.

## Known pre-existing gaps

- Spanish has no `n` sign: the old script referenced `bn.png`, which has never
  existed in that folder.
- A few digraph images ship unused (German `SCH`, Mexican `ll`/`rr`/`nn`); the
  letter-by-letter translator never reached them.
- `privacy.css` and `terms-and-condition.css` are near-identical twins (~900
  lines each) and are the obvious next cleanup.
